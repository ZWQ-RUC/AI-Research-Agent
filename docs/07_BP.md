## 1. 用户痛点（User Pain Points）

研究生、高年级本科生及科研团队在日常高频阅读英文学术论文时面临三大核心瓶颈：
- **效率瓶颈**：单篇 10～20 页的顶会论文包含复杂公式、模型架构与多组消融实验，人工通读并提炼结构化笔记耗时数小时。
- **结构碎片化**：不同论文行文结构差异大，手工整理容易遗漏关键实验设置、数据集规模或方法局限性，难以形成标准化知识资产。
- **信任危机（AI 幻觉）**：通用大模型直接总结长论文时经常张冠李戴、捏造实验指标且缺乏原文页码出处，导致严肃科研场景不敢采信。

---

## 2. 产品解决方案（Product Solution）

**AI Research Assistant** 是一款轻量级、可本地私有化运行的 AI 科研助理工作台，提供三大核心功能闭环：
- **P0 论文智能解析（18 维结构化报告）**：支持上传本地学术论文 PDF，自动完成安全校验与逐页解析，输出涵盖研究背景、研究问题、核心方法、系统架构、实验设计、数据集、评价指标、实验结果、创新点与局限性等 18 个标准维度的结构化报告，并支持一键导出 Markdown。
- **P1 带页码溯源的论文智能问答（Page-Grounded QA）**：将论文按页码与段落切块检索，针对用户提问返回带精确 `[Page N]` 页码与原文片段引用的解答；无原文依据时诚实告知无法确认。
- **P2 零编造实验数据分析（Experiment Analyzer）**：支持科研人员录入自己的 Baseline 与实验组指标数据，自动计算对比变化并生成实验结果概述、原因分析、局限性与后续实验建议。

---

## 3. 产品核心价值（Core Value Proposition）

| 价值维度 | 具体体现 |
| :--- | :--- |
| **真凭实据（Evidence-Backed）** | 每条关键结论强制绑定 PDF 页码与原文原句引用，区分“原文事实”与“AI 推断”。 |
| **数字零幻觉（Verified Numbers）** | 内置代码级数字一致性核验器，自动将报告中的实验指标与 PDF 分页原文逐一核对。 |
| **开箱即用与隐私安全（Local-First）** | 基础运行仅需 Python + Node.js + SQLite，无需安装 Docker 或外部向量库；API Key 后端隔离，支持本地 Ollama (`qwen3:4b`) 离线推理。 |
| **无缝融入工作流（Workflow Ready）** | 一键导出标准化 `.md` 精读报告，可直接导入 Obsidian、Notion 与 Zotero。 |

---

## 4. 产品实现方式（Technical Implementation）

- **前端架构**：Next.js + React + TypeScript + Tailwind CSS，采用现代学术 SaaS 界面设计，集中式 API 管理与三态（加载/空/错误）交互反馈。
- **后端架构**：Python + FastAPI 分层架构（Router 路由层 → Service 业务层 → Database 数据访问层 → Schema 校验层），采用 SQLite 持久化历史报告。
- **文档解析与检索**：使用 PyMuPDF（及兼容引擎）按页提取文本与元数据，识别空白页与扫描件；采用轻量级本地 BM25/TF-IDF 分页检索并支持可选挂载本地 `BAAI/bge-m3` Embedding 模型。
- **多模推理引擎**：统一封装 OpenAI 兼容接口、本地 Ollama (`qwen3:4b`) 与原文确定性提取引擎，兼顾云端高性能与本地 4GB 显存轻量化运行。

## 5. 产品未来发展方向（Future Roadmap）

1. **多篇文献横向对比矩阵（Multi-Paper Matrix）**：支持同时勾选 3～5 篇同领域论文，自动生成数据集、Baseline 指标与方法优缺点的横向对比总表。
2. **扫描版 PDF 公式与图表多模态解析**：接入轻量化版面分析与公式 OCR 工具（如结合 MinerU / PDF2zh 工作流），支持对扫描件及复杂跨页表格的结构化提取。
3. **Zotero 与 Obsidian 插件直连**：提供一键将分析报告与 BibTeX 引用条目同步至本地 Obsidian 知识库与 Zotero 文献库的能力。

## 一、黄金圈法则（The Golden Circle）

### 1. Why —— 为什么需要 AI 研究助理？

在计算机科学、人工智能及交叉学科的日常科研工作中，研究生、本科生及科研团队面临严重的**文献信息过载与结构化消纳瓶颈**：

1. **单篇精读耗时极长**：一篇 10～15 页的顶会论文（如 NeurIPS、ICML、ACL、CVPR）包含复杂的数学符号、模型架构图、消融实验表与多组超参数配置，人工通读并提炼结构化笔记通常需要 2～4 小时。
2. **多源文献缺乏统一知识纲要**：不同作者的写作习惯差异巨大，研究动机、核心公式、Baseline 对比维度分散在不同章节，人工阅读后容易遗漏关键实验边界与局限性。
3. **通用大模型直接总结极易产生“幻觉”（Hallucination）**：将整篇文本直接丢给通用聊天机器人时，模型常会将相关工作（Related Work）中的他人成果误认为本文贡献，或者凭记忆捏造实验指标、混淆页码，导致科研人员不敢直接采信。

**核心使命（Why）**：打造一位**严谨、零幻觉、句句可溯源原文页码**的“AI 学术论文解析员工”，将非结构化的学术 PDF 转化为可验证、可检索、可导出的高密度结构化科研知识资产。

### 2. How —— 通过什么方法完成科研辅助工作？

1. **文档级精确解析与页码锚定**：通过 PDF 底层解析引擎按页提取全文与元数据，保留 `[Page N]` 页码边界与段落拓扑结构，自动识别空白页与扫描件异常。
2. **八模块结构化提示词工程（8-Module Structured Prompting）**：约束 AI 员工严格按照 18 个核心学术字段（标题、作者、年份、会议/期刊、摘要、研究背景、研究问题、研究动机、核心方法、模型架构、实验设计、数据集、评价指标、实验结果、创新点、局限性、结论、后续研究方向）输出 JSON 报告。
3. **原文证据链（Evidence Grounding）强制绑定**：要求每一个核心结论与实验数字必须附带原文原句引用（Verbatim Quote）及对应页码（`page_number`），并对原文未提及的内容强制标注 `未在原文中找到 / 无法确认`。
4. **轻量级本地检索增强问答（Page-Chunked RAG）与实验对比分析**：将论文按页与段落切块，结合本地检索与大模型生成带页码引用的问答回复，并支持用户录入自己的实验 Baseline 与实验组数据进行零编造对比分析。

### 3. What —— 最终交付什么成果？

1. **18 维结构化论文分析报告**：涵盖论文元信息、研究脉络、方法架构、实验数据与批判性评价的完整报告。
2. **可追溯原文证据列表（Evidence Cards）**：每条关键结论与实验指标配套原文片段、所在页码及核验状态。
3. **基于原文页码的交互式论文问答（Paper QA）**：针对论文细节提问，返回带 `[Page X]` 依据的精准解答。
4. **一键导出标准学术 Markdown 笔记**：可直接无缝导入 Obsidian、Notion 或 Zotero 科研工作流。

## 三、八模块提示词设计（8-Module Structured Prompt）

> **声明**：由于不同期次的课程讲义对“八模块提示词”的具体命名存在差异，**本文档明确声明以下采用的是本项目面向学术论文解析场景工程化整理的八模块结构版本（角色定义、背景与目标、输入规范、执行工作流、输出格式规范、防幻觉与约束规则、少样本示范、4A 质量自检）**，不虚构或冒充特定内部讲义原版命名。该提示词已直接固化在后端 `backend/app/services/llm_service.py` 中用于生产环境论文分析。

### 模块一：角色与专业身份定义（Role & Persona）
- **模块作用**：确立 AI 员工的专业学术审稿人与文献精读助理定位，锁定严谨、客观的学术语言风格。
- **提示词内容**：
```text
你现在的身份是「AI Research Assistant —— 首席学术论文结构化解析与证据核验专家」。
你具备计算机科学（AI/NLP/CV/Systems）顶会审稿人级别的文献阅读能力，擅长从英文或中文学术论文 PDF 全文中精准剥离研究背景、核心问题、技术架构、实验设计与消融结论，并将非结构化论文转化为零幻觉、可溯源原文页码的结构化报告。
```

### 模块二：任务背景与核心目标（Context & Objective）
- **模块作用**：明确当前任务的上下文边界与交付价值，防止模型输出泛泛而谈的摘要。
- **提示词内容**：
```text
【任务背景】科研人员需要快速且严谨地掌握一篇上传论文的全貌，并核验其中的实验数据与核心结论。
【核心目标】基于系统提供的带有 `[Page N]` 页码标记的论文提取文本，完成全部 18 个维度的结构化信息提取，并为所有关键结论与实验数字提供原文原句引用（quote）及精确页码（page）。
```

### 模块三：输入材料说明与预处理约定（Input Specification）
- **模块作用**：定义模型接收到的文本格式、页码定界符及元数据结构。
- **提示词内容**：
```text
【输入格式】你将收到以下结构的论文全文数据：
1. 文件元信息：文件名（filename）、总页数（page_count）、PDF 元数据（pdf_metadata）。
2. 分页正文：按照 `=== [Page 1] ===`、`=== [Page 2] ===` ... `=== [Page N] ===` 严格组织的正文文本。
请在分析时以 `=== [Page k] ===` 块作为判断任何句子、公式或表格所在页码的唯一依据。
```

### 模块四：分步执行工作流（Step-by-Step Workflow）
- **模块作用**：引导模型先定位章节与页码，再提取要点，最后做证据交叉核对。
- **提示词内容**：
```text
请严格按照以下五步思维链（Chain-of-Verification）执行分析：
Step 1 [元数据定位]：扫描 Page 1 ~ Page 2，提取论文标题、全体作者、发表年份、发表会议或期刊名称（若为预印本则标注 arXiv 及编号）。
Step 2 [问题与动机拆解]：扫描 Abstract 与 Introduction，分离“研究背景（Background）”、“核心研究问题（Research Question）”与“研究动机（Motivation）”。
Step 3 [方法与架构拆解]：扫描 Methodology / Model Architecture 章节，提炼核心技术路线、关键数学公式/模块（如 Attention 机制、损失函数）及系统架构组成。
Step 4 [实验与数据核查]：扫描 Experiments / Results 章节，提取实验设计、所使用的数据集名称及规模、评价指标（Metrics）以及具体实验数值结果（务必保留原文精确数字与对比幅度）。
Step 5 [批判性总结与溯源]：提炼创新点（Contributions）、原文承认或客观存在的局限性（Limitations）、核心结论（Conclusion）及后续研究方向（Future Work），并为关键结论绑定 `[Page k]` 原文引用。
```

### 模块五：输出结构与 Schema 规范（Output Schema）
- **模块作用**：强制要求输出可被后端 Pydantic 模型直接解析的严格 JSON 结构。
- **提示词内容**：
```text
请严格输出合法的 JSON 对象（不要包含多余的 Markdown 解释文字），必须包含以下 18 个一级字段及证据数组：
{
  "title": "论文完整标题",
  "authors": ["作者1", "作者2"],
  "publication_year": "发表年份（如 2017，无法确认则填 '未在原文中找到 / 无法确认'）",
  "venue": "发表期刊/会议/arXiv编号（无法确认则填 '未在原文中找到 / 无法确认'）",
  "abstract": "摘要核心内容中文结构化概述",
  "background": "研究背景",
  "research_question": "核心研究问题",
  "motivation": "研究动机",
  "methodology": "核心方法详细解析",
  "architecture": "模型或系统架构详细拆解",
  "experimental_design": "实验设计与训练配置（硬件、优化器、步数等）",
  "datasets": ["数据集名称与规模说明"],
  "metrics": ["评价指标名称"],
  "results": "核心实验结果与定量对比数据（必须包含原文精确数字）",
  "contributions": ["核心创新点1", "核心创新点2"],
  "limitations": ["论文局限性1", "论文局限性2"],
  "conclusion": "论文结论总结",
  "future_work": "后续研究方向",
  "evidences": [
    {
      "claim": "AI 总结的关键结论或实验指标声明",
      "quote": "逐字摘录自原文的英文或中文原句片段",
      "page": 1,
      "section": "所属章节名称（如 Abstract / Section 6.1）",
      "fact_or_inference": "原文事实"
    }
  ]
}
```

### 模块六：防幻觉与安全边界硬性约束（Anti-Hallucination Guardrails）
- **模块作用**：切断模型使用预训练记忆脑补未出现事实的路径。
- **提示词内容**：
```text
【防幻觉铁律（违反任意一条即判定任务失败）】
1. 严禁编造论文未提及的内容、作者、机构、发表年份或实验数值。
2. 严禁将 Related Work / Background 中引用的基线模型成果张冠李戴为本文提出的方法成果。
3. 缺失标注原则：凡是在输入文本中找不到明确依据的字段，必须严格填写为 `"未在原文中找到 / 无法确认"`，绝不允许猜测。
4. 事实与推断分离：在 `evidences` 列表中，必须明确标注 `"原文事实"`（直接出自原文句子/表格）或 `"AI 推断"`（基于原文上下文归纳），且所有数字指标必须为 `"原文事实"`。
```

### 模块七：高质量输出示范（Few-Shot Exemplar）
- **模块作用**：提供标准字段颗粒度与原文证据绑定的正例示范。
- **提示词内容**：
```text
【正例示范（以 Vaswani et al., 2017 为例）】
- results 字段正例："在 WMT 2014 英德（EN-DE）翻译任务上，Transformer (big) 取得 28.4 BLEU（训练耗时 3.5 天，8 张 P100 GPU），超越此前最佳集成模型 2.0 BLEU 以上；Transformer (base) 取得 27.3 BLEU。在 WMT 2014 英法（EN-FR）任务上，Transformer (big) 取得 41.8 BLEU（Table 2）。"
- evidences 字段正例：
  {
    "claim": "Transformer (big) 在 WMT 2014 英德翻译任务上达到 28.4 BLEU，英法翻译任务达到 41.8 BLEU",
    "quote": "Our model achieves 28.4 BLEU on the WMT 2014 English-to-German translation task, improving over the existing best results, including ensembles by over 2 BLEU. On the WMT 2014 English-to-French translation task, our model establishes a new single-model state-of-the-art BLEU score of 41.8 after training for 3.5 days on eight GPUs",
    "page": 1,
    "section": "Abstract",
    "fact_or_inference": "原文事实"
  }
```

### 模块八：输出前 4A 自我审查清单（Pre-Output 4A Self-Check）
- **模块作用**：在生成最终 JSON 前强制触发模型内部一致性核查。
- **提示词内容**：
```text
在输出最终 JSON 前，请逐项静默核对以下 4A 标准：
- [Accuracy 准确性]：报告中出现的每一个数字（如 BLEU、F1、层数 N、维度 d_model）是否均能在对应页码原文中找到完全一致的数字？
- [Completeness 完整性]：18 个标准字段是否全部非空？缺失项是否已规范填入“未在原文中找到 / 无法确认”？
- [Applicability 可用性]：方法与实验拆解是否具备足够的工程与学术颗粒度，可供读者直接作为精读笔记使用？
- [Alignment 任务符合度]：输出是否为纯净合法的 JSON 且包含带页码的 `evidences` 数组？
```

## 四、4A 验收机制（4A Acceptance Framework）

> **说明**：本项目从 **Accuracy（准确性）、Completeness（完整性）、Applicability（可用性）、Alignment（任务符合度）** 四个维度建立量化验收机制（若课程原版讲义对 4A 缩写有特定不同定义，此处标注【待结合课程讲义核对】，不擅自声称唯一官方定义）。

| 验收维度 | 验收指标与核查方法 | 通过标准（Pass Criteria） | 代码级自动化校验实现 |
| :--- | :--- | :--- | :--- |
| **1. Accuracy（准确性）** | 核查标题、作者、年份、实验数据集、核心数值指标是否与原文完全一致，是否存在幻觉。 | 关键元数据与实验数字准确率 **100%**；所有提取数字必须通过原文文本子串核验（`verified_in_source = True`）。 | `backend/app/services/llm_service.py` 中的 `verify_numbers_against_text()` 自动提取报告数字并在分页原文中比对页码。 |
| **2. Completeness（完整性）** | 核查 18 个规定分析维度是否全部覆盖，是否包含原文证据链数组。 | **18/18 字段 100% 存在**；若原文未包含某项，必须显式填充 `未在原文中找到 / 无法确认`，不得遗漏键名。 | `backend/app/schemas/paper.py` 中的 `PaperAnalysisResult` Pydantic 强类型校验。 |
| **3. Applicability（可用性）** | 核查输出报告的结构清晰度、学术专业度以及 Markdown 导出的直接可用性。 | 报告分段清晰，包含模型公式/超参数细节，导出的 `.md` 文件可直接放入 Obsidian / Notion 阅读。 | `backend/app/services/markdown_exporter.py` 标准化导出引擎与前端学术报告视图。 |
| **4. Alignment（任务符合度）** | 核查是否严格遵守“防幻觉、给页码、列原文、区分事实与推断”的任务边界。 | 每份报告至少包含 **3 条以上带精确页码与英文/中文原句的证据项**，且标注 `原文事实` 或 `AI 推断`。 | 后端分析流水线强制生成并校验 `evidences` 列表与 `number_checks` 数字核验表。 |

## 五、防幻觉机制设计（Anti-Hallucination Architecture）

本项目不仅仅依赖提示词约束，而是在**解析层、提示词层、后处理核验层、UI 展示层**构建了四重防幻觉工程护栏：

```
[PDF 原始文件]
      │
      ▼
┌──────────────────────────────────────────────────────────┐
│ 第一重：解析层护栏 (PDF Parser Guardrail)                  │
│ - 校验 %PDF- 文件头与损坏状态，拒绝空文件                  │
│ - 逐页抽取并打上不可篡改的 [Page N] 页码锚点               │
│ - 自动检测空白页与扫描版 PDF（字符密度过低时主动阻断并提示）│
└──────────────────────────────────────────────────────────┘
      │
      ▼
┌──────────────────────────────────────────────────────────┐
│ 第二重：提示词层护栏 (8-Module Prompt Guardrail)           │
│ - 强制要求未找到信息标注“未在原文中找到 / 无法确认”         │
│ - 强制要求区分“原文事实”与“AI 推断”                        │
│ - 强制要求每条核心结论绑定 quote（原文原句）与 page（页码）│
└──────────────────────────────────────────────────────────┘
      │
      ▼

└──────────────────────────────────────────────────────────┘
      │
      ▼
```
